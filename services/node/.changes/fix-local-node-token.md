- `deploy-node.sh` no longer writes a node service definition without a token. A deploy given no `--node-token-file` keeps the token the existing launchd plist or systemd unit carries (never printed), and accepts a token in a `.env` in or above the install dir, read exactly as the node reads it. With none of those, it refuses unless `--no-node-token` is passed for a solo-mode gateway. `--no-node-token` refuses a token file, an ambient `FARMSLOT_NODE_TOKEN`, or a `.env` token the node would still use. On Nov 22 a local `deploy-node.sh macwork --instance dev --refresh-cli`, meant only to refresh the CLI, rewrote macwork's plist without its token. launchd kept the loaded job until the Nov 24 deploy re-bootstrapped it, and the node then failed every connection with `token_missing`. The local-deploy message and the release docs now point a CLI-only refresh at `--cli-only`, which never touches the service.
- The node starts when its Run bundle store sits on a volume that is not mounted. It logs that the store is unavailable instead of crashing at load (the dev stack's node on macwork with c910ssd unmounted).
