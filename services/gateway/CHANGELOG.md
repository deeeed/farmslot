# Changelog

All notable changes to `@farmslot/gateway` are tracked here.

## Unreleased

- feat(runtime): fleet-scoped resource claims with a FIFO wait queue. Conflict checks now span every slot a claim's scope reaches — `fleet` always, `machine` when the two slots share a host, `slot` never — judged from the claims and machine each lease persisted at acquire time rather than from a foreign slot's catalog. An acquire that passes `queueOnConflict` takes a durable place in line instead of being refused: it gets a typed `scoped-wait` conflict naming the claim, the holding run, and its position, and `runtime.capability.status` reports the whole fleet-wide queue. Releasing the holder drains exactly the head waiter per freed claim to `acquiring` inside the same write as the release, emits the existing lifecycle event, and finishes the provider boot outside the release lock; a waiter whose owner has already had terminal cleanup is dropped rather than handed a provider nothing would release. Order comes from enqueue time and is never renumbered, so a Gateway restart preserves it. The ADR-054 pre-validation reacquire queues on contention and records the wait on the run, which the work-graph reports as `waitingOn.kind: 'resource'` with the blocking run — a non-empty reason, so the node is not mistaken for the stuck shape the scheduler reclaims. The device-identity guard is unchanged and still refuses a double boot of one physical device; it yields only to an acquire that asked to queue, because that contention is exactly what the queue serializes, so the two never both answer for the same acquire. This is the fleet arbitration the device re-targeting note said would land with the fleet-scoped device claims item.
- feat(posture): re-target validation to another device without re-dispatching the run (ADR-054 item 3). A capability provider's acquire parameters now reach its project hooks: the device-identity subset becomes template variables that beat the slot's configured resource fields, so `{{simulator}}`, `{{avd}}` and `{{adb_serial}}` resolve to the leased device. Every provider action runs with its OWN lease's parameters, so a release stops the device that lease acquired rather than the slot default, and a warm provider held for a different device is health-probed and stopped under its own identity instead of being adopted for, or torn down as, the requested one. `recipe.rerun` accepts a `target`: the Gateway rewrites the matching device requirement in the run's stored proof plan, releases the lease on the previous device honouring the project's keep-warm policy, then acquires the named one — a target no proof capability accepts, or one that fails the identity charset, is refused before anything is released. A device identity is refused rather than escaped if it could carry shell meaning, and a target naming a device another slot's live lease is already driving is refused with the slot and run that hold it; leases stay slot-scoped, so full fleet arbitration with a wait queue lands with the fleet-scoped device claims item. Posture status reports the device each lease resolved to. The cross-slot guard counts a keep-warm lease as a holder — its provider is still up, which is the one state where a device runs under no active lease, and a second slot that adopted it would have had it stopped by the warm sweeper — and it only counts leases on providers that claim a device, so a slot running only a browser no longer reserves its own simulator. A second re-target REPLACES the previous device key instead of unioning with it, and the merged plan is validated before anything is released, so switching from a udid to a simulator can no longer refuse after the device is already gone. Only the parameters a provider's own schema declares are substituted into its hook command. A re-targeted health probe is derived by the same rule as the slot's own resources, so a resource with no health hook is never reported healthy. The guard runs for EVERY device acquire, not only one that names a device: an acquire with no parameters resolves to the slot's configured device, which another slot may have re-targeted onto, and skipping the check there left the common case able to boot a device twice. A device provider reached as another capability's dependency is acquired with the device the plan names for it, so the order a reconciler walks a plan in no longer decides which device is used, and a lease pinned that way is released together with its dependent instead of silently retaining the old device; a refusal caused by such a lease names the dependent and the device it pinned. The stored proof plan records the parameters an acquire actually used, so a later validation cannot quietly send a run back to the slot's configured device. A device identity may no longer start with a dash, which is shell-safe but is still an argument to `simctl` or `adb`. Device identity is scoped to a MACHINE: the pool reuses `fs-1`, `emulator-5554` and avd names across machines, so comparing them fleet-wide refused an ordinary acquire on one machine because another machine ran a same-named simulator. The guard is also told whether a capability claims a device by the registry that already resolved it, instead of re-reading the catalog — a config file mid-write used to make the guard skip itself for exactly the acquires it covers. A device target reaches every requirement whose provider declares the key, claims a device, and sits in one dependency-connected group with the others, so the dev client installed onto a simulator follows the simulator instead of staying on the device the run left; two unconnected device groups are refused, because one target cannot mean both. A platform names the group, not individual members, so a connected sibling whose schema leaves the platform undecided is never split off from its device. A connected member whose schema names a different platform refuses the target before the previous device is released. A platform-only target is refused rather than silently doing nothing.
- fix(lifecycle): completing, failing, and blocking a run now publish the terminal status before any teardown starts, the way cancel already did (ADR-053). The slot release used to run inside the COMPLETE and CI-watch step bodies and the failure cleanup ran before the broadcast, so a run only appeared `done` or `failed` to clients after tmux teardown, provider shutdown, and the slot reset had finished. Those steps now record the release they want and the transition router runs it as an awaited after-effect, in a declared order — backlog settle, work-graph tick, eval harness, slot teardown — with a failure recorded on the transition instead of logged and dropped. A CI-watch chain, a publication gate hold, and a park that already freed the slot each leave the teardown out, so nothing is torn down under its new occupant. A terminal run's slot is held against the orphan reconciler for the length of its teardown, and `resetSlot` now refuses a slot another release already fenced, so the published-then-torn-down window cannot be reclaimed and handed to a new run mid-teardown. A release a terminal step recorded is performed on every terminal route, not only on the completion tail, so a CI outcome of `blocked` keeps its keep-work and keep-warm handoff and its ADR-054 posture reconcile instead of being hard-reset. Failed destructive teardown and failed eval-harness cleanup are recorded on the transition rather than logged and dropped, and a failed backlog settle now leaves the same durable repair marker cancel does. `resetSlot` checks and writes in one conditional update, so a release that fences the slot in between is no longer overwritten, and a failed escalated worker kill leaves the fence up AND reports itself instead of returning as a clean teardown. The releasing fence is stamped with when it went up, and the reconciler reclaims one that has stood far longer than any real teardown with nothing finishing it, so the fence cannot strand a slot for good. That reclaim is its own conditional write rather than the ordinary reset, which refuses every releasing slot and so left the stranded slot exactly as stranded, and its condition is the whole observation the decision rested on — the same fence stamp, still releasing, still no teardown — so a release that landed or re-fenced in between keeps the slot.
- fix(runtime): the terminal capability fence now survives a gateway restart and eviction. Owners and families that have had their terminal cleanup are persisted with the capability store and rehydrated at startup, and an owner past that bound is still refused because acquire also consults the run store for terminal status and terminal resource posture. Restart recovery applies the same fence before it re-adopts a lease: a healthy provider owned by a terminal run is stopped and recorded as `recovery-rejected` rather than promoted back to `acquired`, where nothing would ever have released it. The fence is authoritative for the FAMILY as well as the owner past both bounds, so a live sibling of an evicted terminal family can no longer acquire, and the refusal names whichever of the two actually refused instead of claiming the requesting run had a cleanup it never had. Restart recovery also drops a fenced owner's queued lease, which held no provider but blocked every other run on that capability for good, and its events now say what happened to the provider rather than reporting "released" when the stop failed. The fence retires by AGE rather than by a count of a thousand, in memory on the same write that retires it on disk rather than only at the next restart, and a family is fenced only by an actual family-scope cleanup: inferring it from "any member is terminal" refused a CI-watch chain's own live follow-up run, which shares its parent's family, the moment the parent finished. Because archiving deletes the run record, the durable entries rather than any live-record lookup are the authority, so an archived terminal owner is still refused.
- fix(parking): a stalled runner liveness probe and a stale machine-pause preview each get their own eligibility code — `RUNNER_LIVENESS_PROBE_TIMEOUT` (with the exhausted budget in `details.probeBudgetMs`) and `MACHINE_PAUSE_PREVIEW_STALE`. Both are transient races an operator answers by retrying, and both used to arrive under codes the gateway also emits for real verdicts (`RUNNER_RECOVERY_UNSUPPORTED`, `PARK_EXECUTE_REFUSED`), so telling them apart meant matching the message text. The real verdicts keep their codes. A REMOTE probe counts too: the node RPC deadline used to share the command's own budget, so the transport gave up before the command could report its timeout and the stall was misread as a runner without recovery support. The transport now gets a margin over the command budget and reports its own deadline as a typed error.
- refactor(parking): the gate-park slot-binding predicates now live in `@farmslot/protocol` (`gateParkView` and friends); gateway behavior is unchanged.
- fix(runners): stopping a runner for a park no longer reports a live worker as stopped, or a stopped worker as still running, on a loaded node. The pane-tree liveness probe walks one `ps` snapshot instead of forking `pgrep -P` and `ps -p` per process, and a snapshot that did not happen is now reported as undecided rather than as a confirmed absence, so a failed `ps` can no longer free a slot out from under a live worker. The graceful-exit wait is counted in completed probes under a hard deadline rather than wall clock alone, and a probe that cannot decide fails closed with a typed code (`probe-timeout`, `probe-transport`, `pane-pid-missing`, `runner-identity-ambiguous`) that reaches `MachineParkError.code` instead of a blanket `EFFECT_FAILED`. A snapshot the walk only partly understood, a zombie process, and a pid-reuse cycle are all handled as what they are rather than as a stopped runner. Probes that used to run unbounded are now bounded, a timed-out or failed-snapshot probe is retried with an escalating budget under a wall-clock ceiling that covers the retries rather than only the wait between them, and both the park's pre-flight and slot teardown's pane scan carry that same ceiling. Every step of a stop spends that one ceiling: the pre-flight session-path read, the exact-pane read, the liveness probe, the live session-binding verification and the graceful-exit delivery each used to hold an independent ten-second budget outside it, so a stop could return far past the wall clock its caller granted, and a step that no longer fits is now reported as the probe timeout it is instead of being started. A row whose state column is not a `ps` STAT word condemns the snapshot too: a host whose `ps` omits that column shifts every later one left, and the walk read the runner's own name as a process state on a row it believed it had parsed.
- feat(posture): machine parking reads the project catalog's `affected_resources` instead of guessing from action refs. A provider that declares which slot resources it touches is no longer refused with `CAPABILITY_SLOT_ACTION_UNMAPPED` for acquiring or releasing through a slot action, a resource whose only claimants are `slot-lifecycle` no longer trips `CAPABILITY_RESOURCE_UNOWNED` for running without a lease, and a foreign lease on a declared provider surfaces as `CAPABILITY_FOREIGN_HOLDER` with the resource it holds. Without those two refusals, release-mode parking and `free-slot` can complete on the real fleet, where the sandbox gateway UI runs under the slot lifecycle rather than under a lease. A resource the catalog marks `release_effect: retain` is recorded on the park manifest, left running by the park, verified still running at settle, and verified again by restore rather than booted a second time; a retained resource that stopped while the run was parked fails the restore instead of being silently started. A provider with no `affected_resources` keeps the old derivation, so every unannotated catalog behaves exactly as before. Ownership is checked per claimant, so a lease on one provider never satisfies another provider's claim on the same resource, and a catalog whose providers disagree about what a release does to one resource is refused with `CAPABILITY_CLAIM_CONFLICT` before anything is touched. A resource every claimant retains no longer needs boot and shutdown hooks — parking never stops it and restore never boots it — but it must carry a health hook, because restore has to prove it stayed up and resource polling reports a resource without one as `unknown` whatever its watch config says. A catalog whose claimants disagree is named as a conflict before the hooks are judged, so the operator is pointed at the contradiction rather than at a hooks complaint that follows from it. Restore verifies retained resources before it acquires anything, since a provider's acquire is often its resource's own boot action and acquiring first would revive a dead retained resource and report success over it. A record whose leases were already released is never discarded as zero-effect. Restore now records what it did to each resource on the park record as `restoreEffects` — `verified`, `booted`, `stopped`, or `skipped`, each with an outcome and a reason — and `machine.pause.status` carries it, so an operator reads what happened rather than inferring it from which errors are absent. Those effects come from `executeResourceControl`, the one place a resource's boot, shutdown, or relaunch hook actually runs, attributed to the restore that initiated them rather than to whatever slot they touched — `resource.control`, the chat tool's resource control, and cleanup shutdowns all reach that same function without the machine lock a restore holds, so an operator booting a resource mid-restore would otherwise be recorded as something the restore did and, for a retained resource, fail it over an action it never took. A boot a capability acquire reached and a boot the restore ran itself land in the record identically — an inference from observations taken around the operation could not see a restart of a resource that was already running, and could not attribute anything when two things moved at once. A boot against a resource the catalog retains is recorded as an effect that should not have happened and fails the restore, whatever state the resource was in beforehand, and a resource an acquisition already booted is not also reported as verified.
  **One-time operator action, not just a re-acquire:** the field is part of the provider provenance digest, so on the deploy that annotates a project's catalog every live lease of that project stops matching its provider. Release cleanup then refuses with `Provider provenance changed; cleanup refused` unless forced, and after a restart each restored lease errors with `Stale or missing provider provenance after restart; cleanup refused`. Those leases need an operator to clear them. Drain the fleet before rolling this out.
- feat(posture): `free-slot` at a publication gate frees the slot. Machine-pause release eligibility accepts a gate-held run as a third shape beside monitor and ci-watch, gated on the runner's declared graceful exit and persisted session reload; a runner declaring neither is refused with `RUNNER_RELOAD_UNSUPPORTED` and nothing is stopped, and an orchestration-only park of a gate-held run is refused rather than stranding its gate. A park stops the worker and its manifest resources, detaches the run's branch after refusing with `WORKSPACE_NOT_PRESERVABLE` if the tree has uncommitted work, then releases slot ownership while keeping the park record, the run's `slotId`, and the pending gate decision intact; the run stays at its gate rather than moving to `paused`, so the next occupant's prepare cannot reset the parked branch. The detach and the release are journalled as one `free-slot` intent and finished on restart, so a crash between them cannot leave the slot bound to the parked run. While a park is in flight or landed, `run.resolveDecision` and `runtime.posture.apply` refuse with a typed reason, restart recovery skips every slot-bound repair for the parked run, a successor's `slot.release` no longer detaches its binding, auto-recycle skips the freed slot, `machine.pause.status` reports the recorded residuals rather than the successor's providers, and the engine's gate path blocks rather than fails so the run can still be cancelled. Cancel clears the record and leaves the slot alone. A park that fails part-way stays fenced while any of its effects is outstanding — a stopped worker included, so nobody answers a gate the worker cannot act on — and `machine.pause.restore` accepts it as the way back, since a gate park preserves the run's status rather than pausing it. A detach that landed is rolled back when the release cannot follow, but never onto a slot a successor already owns or a tree that moved, and the write-ahead intent is dropped at the same time so a later reconcile cannot re-drive an abandoned free. `machine.pause.restore` carries a gate park all the way through: preview, preflight, and the resume transition each know a gate park preserves the run's status instead of pausing it, so the restore that reloads the worker now completes and reports what it did rather than throwing after the fact. A park whose gate loop had already exited, because resolution raced the park, is restored by replaying the gate rather than refused for having no running step, and that replay is attributed to the operator rather than charged against the auto-recovery budget. A restore that cannot put the detached branch back reports failure and keeps the fence instead of claiming success over a workspace the run cannot use; it checks the workspace before anything that advances the run generation, so a failure there leaves the record retryable rather than permanently refused as GENERATION_CHANGED. A restored gate does not inherit the `free-slot` choice that parked the run, so it cannot re-park before the operator sees it, and a wait boundary reached while a park is still in flight declines to act. Slot teardown, auto-recovery, and the post-resolve resume timer all leave a parked run alone, and the intent is journalled per run so one batch member's success cannot erase another's pending repair. Dispatch scoring treats a park-freed slot's detached HEAD as idle only while the checkout is evidence for itself — the slot still sits on the commit the park detached to, or the row still names that park's run — so a stale record cannot excuse commits a later occupant left behind. Every other detached slot still scores stale and still trips the unmerged-work refusal on release. The successful park is now proved live: a claude backlog run held at its publication gate on `macwork-ff-1` was previewed `ELIGIBLE_GATE_RELEASE_PAUSE`, freed through `runtime.posture.apply`, and settled `parked`/`freed` with its branch preserved, its worker stopped, its gate unresolved, and a successor run dispatched into the slot. Restoring a freed park lands it back in the ORIGINAL slot: answering the pending gate is itself the trigger, so `run.resolveDecision` re-binds the slot, puts the preserved branch back at its recorded tip, reacquires the manifest's capabilities, reloads the persisted runner session, and only then consumes the decision. `machine.pause.restore` drives the same path. The recorded tmux pane is not part of the contract — freeing the slot hands its tmux session to the next occupant, whose dispatch replaces the windows in it, so the runner capability layer re-hosts the session on a fresh pane in that slot and writes the new target to both the park record and the run's agent context, refusing rather than respawning over a pane a runner is still alive in. A refused restore changes nothing an operator has to undo: the record stays parked, the decision stays pending and answerable later, and the typed reason is durable on the record — `RESTORE_SLOT_TAKEN` when another run holds the slot, `RESTORE_WORKSPACE_UNAVAILABLE` when the successor left uncommitted work or moved the branch, `RESTORE_RUNNER_RELOAD_FAILED` when the session cannot be reloaded with a structured acknowledgement. Re-dispatching into a DIFFERENT slot is still a separate item. The slot claim is journalled as a `restore-slot` intent and finished on restart, so a crash between the claim and the record write cannot leave a row bound to a run every reader still treats as freed. A restored gate does not inherit the `free-slot` choice that parked the run for one wait boundary, whether the gate was held or replayed, so answering it cannot hand the slot away again before the operator sees the outcome; a replay presents a new decision, so resolving through it reports `RESTORE_GATE_REPLAYED` instead of consuming a decision nothing is waiting on. A park still in flight is refused as before with `GATE_PARK_IN_FLIGHT`. What a restore still owes is tracked as its own stage sequence — re-bind, re-attach, re-acquire, re-load — written before each stage and completed after, and never inferred from whether the run currently occupies its slot: a reload that started the worker and then failed to be acknowledged leaves an occupied slot and a running process, and answering the gate there drove the engine against a worker that never confirmed it came back. Consuming a gate now requires a restoration that recorded an acknowledged session reload, a retry re-runs every stage idempotently (so an attach target a previous attempt left on a destroyed pane is repaired), the write-ahead marker is kept until the last stage lands so a crash before the checkout cannot drop it while the branch is still detached, restart repair resumes from the recorded stage and finishes the two stages that would otherwise strand the fleet, and a gate restore that finds a concurrent one already finished reports that restoration instead of failing for a race the operator cannot see. Re-hosting a parked session now probes every runner that could be alive under the target pane rather than only the parked run's own, so a surviving successor of another runner is seen instead of being respawned over, an unreadable process tree refuses rather than assuming the pane is empty, and adopting a live worker requires evidence that the pane belongs to this run — a matching session id proves the conversation, not which run owns the process, and that evidence must be the slot row naming this run right now rather than a pane the record remembers. A worker the restore adopted rather than relaunched is recorded with its own `adopted` acknowledgement kind and no turn token, so a client can tell an inherited worker from a delivered turn; both satisfy gate consumption, because the question is whether this run's worker is back on its persisted session, not who relaunched it. A record that still owes a restore is never settled as a zero-effect repair: that repair writes `restored` with no stages and no proof, which would drop the consumption fence and let the next answer skip the restoration entirely.
- fix(posture): keep-warm cleanup reports only what it achieved. A stop that failed or was deferred is reported as such rather than as `stopped` or `applied`, a provider whose stop failed keeps whatever it depends on, and `runtime.capability.stopWarm` reports a capability an active lease still holds as running.
- fix(posture): a warm provider left over from an older provider definition is cleaned up through that definition's own release action before a new one starts, and an acquire that finds an expired keep-warm lease health-checks it before starting a second instance. When the old definition has left the catalog the acquire fails closed and names the lease instead of guessing a release action that could stop the wrong provider.
- feat(posture): `runtime.capability.stopWarm` stops a single warm provider through the registry's dependency-safe warm sweep. `runtime.capability.release` cannot: it only considers leases that still hold a provider, so for an already-released warm lease it reported success while the process kept running. A capability an active or still-warm dependent needs is deferred with that reason rather than stopped, and a failed cleanup reports the provider unhealthy instead of stopped.
- refactor(posture): `observedStateForLease` moves to `@farmslot/protocol` so clients share the Gateway's derivation of a provider's observed state instead of re-deriving it.
- fix(posture): `runtime.posture.preview` for a `free-slot` gate choice now answers exactly as apply would — the same park-ineligible rejection with an empty plan when the run cannot be parked, and a no-op plan when it is already parked — instead of previewing a plan that cannot run or reporting a rejection for a run apply treats as a success.
- feat(posture): the Gateway now owns one resource posture per run (ADR-054) and applies it at durable operator waits, validation preparation, recipe rerun, cancel, and family terminal cleanup. Waits shed what the next operator action does not need, validation reacquires and health-checks its proof plan before running, and terminal stops every run- and family-owned provider in dependency order. Policy resolves gate choice over the run's `waitPolicy` over project defaults over framework defaults, and the winning source, desired disposition, observed provider state, and any cleanup failure are persisted on the run for reconnecting clients. New RPCs: `runtime.posture.status|preview|apply`.
- feat(tmux): add `tmux.pasteText`, which delivers text to a pane as one bracketed paste buffer and optionally submits it. `tmux.sendKeys` types keys and chunks them, so a multi-kilobyte command can arrive truncated and strand the shell at a continuation prompt with nothing executed.
- feat(runners): record each agent context's runner session identity through one runner-layer hook at launch, branch-affinity nudge, retained handoff, reviewer bind, and self-review/CI fix relaunch, and add `run.sessionCommand`, which returns the gateway-built command that reopens that exact session (including a Codex worker's isolated `CODEX_HOME`), the slot's tmux attach line, and structured runner liveness that is `live` only when the pane's runner owns that exact session. Runners without a validated session reload return a typed `unsupported` reason instead of a guessed command, and the result carries the runner's declared graceful exit from the capability registry. When the recorded window is gone — dispatch destroys a role window once its runner exits — the gateway scans the slot's tmux session for the pane that owns that exact session and reports it live at that exact pane, so a reopen pasted into any window is visible in Command Center and the CLI. The agent context is rebound only when the requesting run still owns the slot, re-checked immediately before the write; after a warm handoff the result reports `ownership: 'transferred'` with the successor run id and mutates nothing, and an unreadable slot row reports `ownership: 'unknown'` and also blocks the write. The attach line selects the exact pane, so a split window cannot land the operator on a sibling. The slot-status mirror is compare-and-set on the same ownership as the write, so a transfer landing between the two writes cannot clobber the successor's agent contexts. A pane that cannot be probed leaves liveness `unknown` instead of claiming the session is gone.
- fix(runners): recognize a RESUMED runner session. Fresh-launch attribution binds only sessions whose transcript is newer than the pane process, which a reopened conversation can never satisfy — its transcript was written by the process that has since exited. Codex now proves ownership from the live process's own resume argv through a runner-capability check, so a reopened session is reported live at its new pane instead of staying `dead`. Ownership is certified by the process holding that exact rollout file open, which is a kernel fact about the pid; argv does not gate the decision at all and is recorded only as diagnostic metadata, because `ps` flattens it into a display string where a value containing spaces can both hide the real session argument and impersonate one — it could falsely reject a valid resume as easily as accept an invalid one. `--last`, unrecognized flags, and variadic flags all yield unknown liveness rather than a guessed certification.
- fix(runners): the operator-facing reopen command is wrapped as a single `bash -lc '…'` invocation so it survives an interactive shell. The observability installer's `*[!0-9a-f]*` pattern made zsh apply history expansion to `!0` and abort the whole pasted line with `event not found: 0`; tmux launch paths were unaffected because they run non-interactively, and they keep the unwrapped command.
- fix(tmux): a `send-keys` that tmux refuses now throws instead of reporting a successful delivery, and interactive target readiness compares the window tmux actually resolved. `session:window` silently resolves to the session's current window when that window no longer exists, so input aimed at a destroyed role window was landing in an unrelated one and being reported as delivered.
- fix(review): preserve the pre-fix HEAD across restarts, re-review partial fixes before keeping an external blocker (also when the fix delta cannot be read), never publish that re-review as a passing independent review, discard consumed reviewer plans on explicit gate replay, record recovered dispatch only after the slot reclaim succeeds, refuse a dispatch replay when the worker signal cannot be read instead of resending over a possibly live worker, and let operators close a blocked reviewed run with its already-linked PR number without a stale engine loop reopening it.
- fix(runners): a runner-aware `dispatch_cmd` without a `{model}` placeholder no longer drops the selected model: cursor, grok, and codex now receive `--model` (and grok its effort flag) after whichever binary placeholder the template invokes, including a bare `{runner}`, and exactly once, so a dispatch cannot silently start on the CLI default. Model and effort values are quoted unless they are bare shell-inert tokens, so a value carrying spaces or metacharacters can no longer split into extra arguments or run a second command; a template must therefore not add its own quotes around `{model}` or `{effort}`. A model or effort value that is empty or starts with `-` is now refused with a typed error naming the value, because quoting stops the shell but every runner CLI still parses such a value as one of its own options.
- fix(orchestration): preserve run and worker-signal state across recovery, adopt delayed exact acknowledgements without relaunching live workers, and isolate gateway tests from live fleet state.
- fix(publication): refuse dev and fix-bug packages that lack `pr-description.md` or omit and reorder sections from the repository's live PR template.

- feat(dispatch): keep unowned runner sessions warm and expose them as replaceable candidates on every node; a selected fresh dispatch reserves the slot against races, terminates all retained runner panes without typing into their composers, then prepares normally.

- fix(gateway): a warm handoff pins usage accounting at the retained transcript's last record boundary, so a run is charged only for what it appends. Previously the parent's history was charged to the child and update-branch runs breached their ceiling minutes after starting. Runner session-usage providers now all report increments — codex converts its session totals in its own provider rather than the budget guard compensating for them. The pin is flushed with `persistRunNow` before the warm prompt is delivered.

Text typed at a busy composer is never submitted, so it accumulated there while the retry budget drained and the worker never heard about the breach.
