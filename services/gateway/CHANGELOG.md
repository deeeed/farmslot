# Changelog

All notable changes to `@farmslot/gateway` are tracked here.

## Unreleased

- fix(gateway): Grok directory-trust ready-timeout no longer ignores a confident classifier `trust_prompt`/`send_yes` — `sendRunnerPostLaunchPrompt` retries deterministic blocker auto-actions up to twice, extends the readiness deadline by half the budget after a blocker is auto-resolved, and on classifier fallback re-captures the pane and requires the deterministic trust detector to confirm an actionable prompt on that fresh capture before delivering the keystroke (classifier confidence alone never authorizes a send). Runner-validation gains fixture scenario `dispatch-prompt-trust`.

- feat(gateway): per-flow monitor timeout overrides (`monitoring.flows.<flowType>.total_timeout_min` / `stuck_timeout_min`, falling back to the project-level value then the built-in default) and interactive-handoff auto-recovery — a pending `monitor_interactive_handoff` decision resolves itself when a fresh terminal SIGNAL.json lands on the slot (push subscription + fallback poll), and startup recovery re-arms that watcher so a signal written after a gateway restart still auto-resolves. Unattended resolution requires a verifiable signal timestamp: missing/unparseable timestamps are rejected on this path (operator-confirmed paths stay lenient), and the fallback poll guards its probe so a failed read can't become an unhandled rejection.

- feat(gateway): in-flight publication reviews survive a gateway restart — on human-gate re-entry, a reviewer context still marked in-flight whose task dir holds a fresh terminal signal + parseable feedback is ingested into `publishGate.independentReviews` instead of being discarded (mirroring fix-pass recovery). Only cleanly completed signals stamp verdicts (failed/blocked reviewers never certify), and freshness anchors on the new `AgentContext.attemptStartedAt` so neither warm context reuse nor the startup reconciliation `updatedAt` rewrite can misclassify a signal. Remaining coverage gaps (completed-before-append window, reviewer-still-running at restart, package refresh) are documented follow-ups on the PR.

- feat(gateway): Claude send decisions are hook-only unconditionally — the ADR-032 Phase 3A shadow flag (`FARMSLOT_OBS_PANE_RETIRED`, per-runner `observabilityPaneRetired`/`observabilityPaneRetirementEnvFlag`) is removed and `isRunnerPaneRetired` becomes intrinsic (`event-driven` + hook provider + `requiresBusyComposerPoll !== true`); Codex keeps its pane fallback. `parseClaudeCtxPctFromPane` is demoted to a debug helper (statusline is the sole ctx-% source). Shared pane branches consumed by run-monitor/self-review/ci-monitor are intentionally retained pending their hook migration.

- feat(gateway): ADR-032 Phase 3A Claude pane-regex shadow retirement (MANUAL-000003). Dark-launch flag `FARMSLOT_OBS_PANE_RETIRED` routes claude send decisions through a hook-only path that consults observability (hook/statusline) instead of capturing the pane before the send: a hook-authoritative idle sends fresh, a high-confidence prompt-digest match reports already-delivered without resending, and a degraded hook reading (unknown liveness) holds the send and emits an `observability-degraded` attention plus deterministic recovery instead of falling back to a blind pane submit. Non-authoritative hook readings are preserved in the Phase 3A agreement log rather than dropped, so shadow disagreement stays observable. Flag off (default) = unchanged pane-based behavior.

- fix(gateway): safe-send no longer presses Enter on an empty composer. An authoritative hook reading of "prompt digest not accepted" was treated as proof of a buffered instruction, so `sendRunnerInstructionSafely` submitted an existing (nonexistent) instruction — reporting success while nothing was ever typed. This silently broke self-review fix-task delivery to claude workers (three consecutive delivery failures on one run: wedged, freshly relaunched, and warm-idle panes alike). The submit-existing path now requires the pane to actually show the buffered instruction; otherwise the message is typed via the normal pane-clear/busy-aware path.

- feat(gateway): same-run warm review session policy (MANUAL-000009). `self_review.session_policy` (project.json) selects `fresh-per-pass` (default — unchanged kill/relaunch per pass) or `warm-per-reviewer`, which resumes the SAME reviewer runner session (`claude --resume` / `codex resume` / `grok --resume`) for re-reviews within one run's review loop and narrows the re-review prompt to the worker's fixes since the previous findings. Warm reuse is scoped strictly to one run — a claim requires exact `runId` + task dir + artifact scope + runner + subject lineage (run branch) — and sessions become forensic-only (never claimable) on review-gate exit, run cancel, and slot release; a later or unrelated run can never resume another run's reviewer. Per-loop artifacts (`review-loop-N`, fix deltas, usage, reviewed head) are unchanged in both modes. `SelfReviewOptions.reviewSessionPolicy` overrides per call; runners without persisted session reload (cursor) always run fresh.

- chore: comment-only sweep — code comments describe rationale inline instead of citing ticket numbers (no behavior change).

- refactor(gateway): ready-gate and publish-package decision labels read _Request Independent Review_ / _Request Independent Review (runner diversity)_ (action ids `request-extra-review` / `request-cross-runner-review` unchanged for replay compatibility); review artifact verdict suffix and gate messages use independent-review/runner-diversity language (MANUAL-000008).

- fix(gateway): launch-plan restart + replay residuals (MANUAL-000038). Restart reconcile now links a `dispatching` launch-candidate queue row to its durable run (matched by candidate key + `launchAttempt`) and drops it instead of re-queuing — a re-dispatch would mint a second run with the same attempt and alternate candidate ownership; rows whose run was never created still re-queue safely. The failed/needs-attention observation gate is candidate-aware: a launch-plan candidate observation (plan id + membership verified) passes through to the per-candidate attempt guard, so replaying a failed comparison candidate updates its projection and re-derives the item status instead of staying terminally failed while the replay runs.

- fix(gateway): launch-plan run observation gates candidate updates by ownership + a monotonic attempt sequence (MANUAL-000037). Each (re)enqueue of a launch-plan candidate stamps its queue item and run with a strictly increasing per-candidate `launchAttempt` (persisted on the candidate projection), and `applyLaunchPlanRunObservation` rejects observations from a foreign plan or unknown candidate and drops any event whose attempt is lower than the candidate's current owner. A re-enqueued run carries a higher attempt from its first update — even before `markBacklogRunStarted` transfers ownership — so it takes the candidate over, while a late echo from a superseded run can no longer overwrite a candidate projection or steal the baseline's item-level run link. The attempt is clock-independent and persisted, so same-instant re-enqueues, clock rollback, and restart are all handled (superseding the earlier wall-clock approach). New fields: `QueueItem.launchAttempt`, `Run.launchAttempt`, `RunCreateParams.launchAttempt`, `BacklogLaunchCandidateProjection.attempt`. Comparison-candidate replay while the plan is terminal (blocked upstream in `shouldApplyLinkedRunObservation`) and restart-reconcile ranking remain documented follow-ups on MANUAL-000037.

- fix(gateway): multi-PR backlog items no longer auto-close on the first merged run (MANUAL-000035) — `applyRunObservation` returns a `multiPr` item to `ready` when its linked run finishes, keeping the next slice dispatchable; failure/needs-attention observations and the explicit `backlog.closeShipped` final closure are unchanged. `backlog.update` accepts `multiPr` (not a lifecycle key).
- fix(gateway): fix-delivery reliability (MANUAL-000029/000028) — self-review fix sends now verify the worker visibly reacted within 60s of a sent=true delivery (a context-saturated REPL swallows prompts with a frozen pane) and fail loudly instead of burning the fix timeout; a worker at ≥90% context is relaunched fresh before fix delivery; the self-review relaunch path ports PR #326's live-runner verification (no more blind trust in respawn, failed relaunches correct the optimistic `working` context). Reviewer/worker launches classify usage/rate-limit banners as a `usage-limit` launch blocker (loud early failure naming the quota instead of a generic readiness timeout), re-enforce the minimum tmux window size right before readiness polling and review-completion polling (5-row reflowed panes truncate the lines matching depends on), and extend the readiness deadline once by half the budget when the pane is still actively painting at expiry (slow cold starts).
- fix(gateway): watched CI checks now classify skipped jobs as `skipped` instead of perpetual `pending` — `matchCheckGroups` normalizes raw `gh pr checks` statuses in the no-groups path, group aggregates treat skipped shards as neutral (a skipped shard no longer holds a group pending or blocks a pass; an all-skipped group reports `skipped`), and `allPassed` asserts when nothing failed or is pending and at least one check passed. `PRStatus.checkSummary` gains a `skipped` count and `checks[].status` a `skipped` value, so path-filtered CI jobs stop showing PRs as forever-pending on `pr status`/`pr list`/dashboard surfaces.
- feat(gateway): slot helper methods `slot.monitor`, `slot.show`, `slot.softRefresh`, `slot.reopen`, `slot.autoRefresh` in `methods/slot/helpers.ts` — TS ports of the retired `monitor-slot.sh`/`show-slot.sh`/`soft-refresh-slot.sh`/`reopen-slot-browser.sh`/`auto-refresh-slot.sh`. Command composition + guards (emulator-resource check, RECIPE_HARNESS_ROOT path validation, `soft-refresh.js`/`reopen-browser.sh` existence) run in TS; ssh/tmux/CDP side-effects go through `execOnSlot` (local/remote), with `slot.autoRefresh`'s orchestrator tmux monitor on `execLocal`.
- fix(gateway): worker completion for worker-owned-push flows (pr-complete, update-branch) now verifies the branch is committed and pushed before the run advances — on unpushed work the engine sends one publish nudge, waits bounded time, then blocks the run with a truthful reason instead of ci-watching a stale SHA. CI-fix and self-review fix-task sends retry once with a busy-composer poll when deferred and fail the attempt loudly instead of burning the wait timeout; warm-worker relaunch verifies a live runner is actually in the pane before reporting success; key self-review loop lifecycle logs (issues found, feedback sent, fix timeout, relaunch failures) are always-on instead of DEBUG_SELF_REVIEW-gated.
- feat(gateway): chained CI-watch merge-conflict follow-ups dispatch as `update-branch` (renamed from `merge-main`) with a default `branchUpdateStrategy: rebase`, resolving the PR ref (`owner/repo#N`) from CI metadata for all PR-bound chains — including manual/Jira-rooted families that previously threw `Invalid PR reference`. Load-time run-store migration normalizes legacy `flowType` and CI decision action ids/labels so the old name never surfaces.
- fix(gateway): self-review issue parsing is scoped to the `## Issues` section (whole-document fallback for legacy artifacts), strips fenced code blocks before section extraction (backtick/tilde, info-string-aware closing, unterminated → EOF), accepts CommonMark 0–3-space indentation and numbered/title-style findings with indent-aware nested-bullet folding, prefers path-looking backtick locations, and skips placeholder bullets — Evidence/Validation bullets no longer leak into fix passes and numbered findings are no longer dropped. An incomplete post-fix re-review now surfaces as skipped instead of silently clearing the reviewer's issues.
- refactor: `runtime/session-usage.ts` consumes the ported `@farmslot/slot-config` core directly instead of shelling out to `scripts/session-usage.sh`; `computePRRecommendation` moved to `@farmslot/protocol` (re-imported) with the bash pr-monitor rules folded in — `PRStatus` gains `workerActive` so formatters can derive the worker-active sub-labels.
- refactor: `core/config.ts` and `core/hooks.ts` moved to the new `@farmslot/slot-config` package (gateway files remain as re-export shims; `SlotConfigError` serializes like `GatewayMethodError` in RPC responses). No behavior change.
- refactor: dispatch `isCdpLive` now delegates to the shared protocol `isCdpLiveValue` (no behavior change).
- fix(gateway): retarget task-local `./mark` via `checklist-target.json` when nested-loop roles activate, so self-review and CI-fix progress marks the active checklist instead of worker `TASK.md`; restore worker target on replay and role completion.
- fix(gateway): use structural try/finally restore for self-review-fix and CI-fix role bodies so new exit paths cannot skip worker checklist-target reset.

- Active-development baseline; add user-facing changes here before release or package publication.

## 0.2.2 - 2026-07-09

- fix(gateway): stream prepare output on the single `script.output` channel and record output lines by event name, so a run's persisted `lastOutput` no longer doubles every prepare log line
- fix(gateway): recover the real signal exit code (129 SIGHUP / 143 SIGTERM) when a prepare tmux window is torn down externally instead of masking it as a generic exit 1, surface a "window killed externally" hint, and scope the pre-launch `prepare-*` sweep so it never SIGHUPs the current run's own windows
- fix(gateway): drop stale step-owned decisions (`monitor_*` / `ci_*`) when replaying a run from an earlier step, so a prior generation's interactive handoff no longer re-blocks the reset run
- feat(gateway): backlog archive/delete/restore support; the archivable-status set is now imported from `@farmslot/protocol` instead of a local duplicate
- fix(gateway): thread the resolved install workspace into slot prepare/provision subprocesses. The prepare tmux window inherits the gateway env, which may not carry `FARMSLOT_WORKSPACE`; pack runway scripts then default the workspace to `$HOME/farmslot`, so a dev-farm slot wrote `.runway-resolved` and provision artifacts into the base install's workspace. `buildPrepareWrappedCommand` now exports the workspace root resolved via `resolveWorkspaceRoot` (mirroring the CLI's `resolveWorkspace` contract: `FARMSLOT_WORKSPACE` env → parent of the farmslot clone holding `state.json`). No-op when the env already sets the workspace; unset when no workspace resolves so the pack default still applies
- feat(gateway): recipe-run artifact ingestion reads and validates `resolved-recipe.json` when present — the fully-composed recipe is checked in full (including flow-call resolution), while `recipe.json` stays envelope-only, so library-composed recipes are validated without rejecting them for unresolved `call.ref`s
- feat(gateway): optional TLS listener. When `FARMSLOT_GATEWAY_TLS_CERT` + `FARMSLOT_GATEWAY_TLS_KEY` are set, the gateway also serves `wss://` and https `/health` on a second port (`FARMSLOT_GATEWAY_TLS_PORT`, default 7778) alongside the existing plaintext `ws://` port, so a hosted HTTPS Command Center can reach a local gateway again (Chrome 150 blocks `ws://` from https origins as mixed content). No cert configured leaves behaviour unchanged; a bad TLS config degrades to `ws://` with a teaching log instead of crashing the control plane
- fix(gateway): rewrite the task-local `./mark` wrapper on every checklist-target sync so replayed or legacy task dirs pick up task-dir mode instead of stale explicit `TASK.md`/`SIGNAL.json` shims
- fix(agent-runtime): drop legacy explicit-args mark surface; task-dir + manifest is the only supported invocation
- fix(gateway): treat self-review progress `SELF-REVIEW-SIGNAL.json` (`status: running`) as non-terminal and require `review-feedback.md` before declaring review complete
- fix: reset failed graph-linked backlog items to `ready` when their run is deleted or missing, clear stale run linkage on Mark ready, and retry graph enqueue when a prior completed scheduler ledger entry is stale
- feat: validate `hooks.recipe_run` and live-rerun artifact packages against Recipe Protocol v1, and prefer typed `artifact-manifest.json` metadata for live recipe artifact rendering with legacy scanning only as fallback
- feat: add the `artifact_available` prepare requirement. A profile can gate its cheap path on a project-declared `artifact_check` hook — a fast (seconds) probe reporting whether the profile's prebuilt artifact could be resolved. Exit 0 runs the profile; any non-zero exit walks the profile's declared fallback with the probe's last output line as the failure detail. A missing hook fails the requirement with `project has no artifact_check hook`. The run's work ref is threaded to the hook as `{{prepare_ref}}` (empty when the run has no work branch) and the project default branch as `{{prepare_default_ref}}`, so a probe can order its own resolution (work ref first, default ref fallback) and check the ref the run will run, not the slot's pre-checkout HEAD (selection precedes the git phase). `{{slot_id}}` is available for slot-scoped probe state. `expandHook`/`expandTemplate` gained an optional per-call `extraVars` map to carry them. Unknown requirement kinds keep failing `validatePrepareConfig` loudly, so an old gateway reading a config that declares `artifact_available` surfaces a teaching error rather than silently degrading
- Consume the protocol-owned `RecipeQualityArtifact` validator and render worker task helper paths from `@farmslot/agent-runtime`
- fix: local slots now show `[connect] Local slot on <machine>` instead of the misleading `[ssh]` messages during prepare — the SSH probe and labels are skipped when `isLocal` returns true
- fix: deps phase now streams install output to the CLI in real time; previously the tail-poll ran but output was silently dropped because no `onOutput` callback was wired
- feat: deps phase emits a `[deps] Still running… (Xm since last output)` heartbeat step every 30 s of silence so long yarn installs remain visible
- fix: raise the local fixture-sync backstop from 60 s to 5 min (it sat on top of the real 55–60 s single-domain runtime, killing healthy prepares at exit 124), and, on timeout, teach the escape — elapsed vs limit, log path, the exact `farmslot slot prepare` re-run, and the working override (add `FARMSLOT_FIXTURE_SYNC_TIMEOUT_MS` to the gateway `.env` and restart, since a CLI-side env prefix never reaches the running gateway)
- fix: restart recovery only skips prepare when nothing was terminated and the recorded prepare sub-steps show it completed its phases (a terminal `health` sub-step). Termination of a live in-flight prepare process is now reported precisely by `clearStalePrepareProcess`, so a health probe against artifacts a just-killed preflight was still refreshing no longer marks a half-prepared slot healthy and advances it to dispatch — recovery resets prepare and re-runs it instead
- feat: the generated task-local `mark` wrapper resolves the published `@farmslot/agent-runtime` bin at run time via a resolution ladder (`FARMSLOT_AGENT_BIN` env override → `farmslot-agent` on `PATH` → recorded farmslot-install `mark-checklist-step.cjs` path → teaching error, exit 127), instead of hard-coding the path into the farmslot node install. Dev/farmslot-checkout slots (where the bin is not on `PATH`) keep the previous behaviour via the recorded-path rung
