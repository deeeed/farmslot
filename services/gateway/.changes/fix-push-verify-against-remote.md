- Push verification asks the remote what it holds for the run's branch (`git ls-remote`) instead of trusting the local `origin/<branch>` ref. A slot clone that fetches main only never moves that ref on push, so a stale copy counted pushed commits as unpushed and blocked the run although GitHub had them (F326, Terminal #298). A remote commit the clone lacks is fetched first. A branch the remote doesn't have stays unpublished even if a stale local ref matches. If the remote can't be reached, the local comparison is used as before. Commit-mode inspection never contacts the remote.
