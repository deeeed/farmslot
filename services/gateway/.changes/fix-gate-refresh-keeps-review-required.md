- A package refresh keeps a review the operator requested at the gate. Refreshing a gate, which reading it can trigger when its head moved, reset the review minimum to the project default, 0 for dev, and the card, resolve and finalize all read that lowered policy, so `approve-publish` could publish a head with no review. The requirement now holds until a review at the package's head satisfies it.
- A gate presented again with the same head, review subject and description keeps its decision id across a replay or restart. A changed package still gets a new id, and a stale approval is refused because it binds to the package, not the id.
