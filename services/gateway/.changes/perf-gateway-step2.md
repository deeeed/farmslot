- Local fleet slot checks and the pending-decision walk run in a `gateway-background` child process, off the request loop, and local fixture hashes are read in-process and reused while a file is unchanged. If the child is down, fleet refreshes, decision resolution and a decision listing with no earlier scan fail, and gateway.doctor's "Background process" check says so; `FARMSLOT_GATEWAY_BACKGROUND=0` runs these probes in-process. Each command the child starts runs in its own process group, killed when the child stops, loses the gateway or exits; a command with a timeout also ends by itself a few seconds after its timeout if the child is killed outright.
- On local slots, fleet refresh, the branch watcher and the gateway update check read HEAD, refs and git config from the checkout's files instead of starting git, with the same answers; layouts outside the covered cases still run git: reftable or another repository format, config files that include others, and config git would refuse, or that sets a variable this check does not know in a section git checks at startup.
- Publication secret scanning runs on a worker thread, so a large log no longer holds the gateway for seconds. Publication waits for the completed scan and refuses when the scan fails, is stopped, or 32 scans are already waiting.
- Runner progress files on remote slots are read through the node's `fs.readText` and `fs.isFile` instead of a shell per poll; nodes that do not declare the reads keep the shell read.
- GitHub reads and writes run in the gateway process over HTTP instead of one `gh` process per request, with ETag revalidation so unchanged data costs no rate limit. `gh` is still used to read the keyring token and sign-in status and to find a slot's PR from its checkout when the project names no repository; the token is re-read at most once a minute, so `gh auth switch` takes effect within a minute. `FARMSLOT_GITHUB_API_URL` points every GitHub host at one origin for fixtures and proofs; with it set, the keyring is never read and only `FARMSLOT_GITHUB_FIXTURE_TOKEN` is sent.
- Commands a host service starts outside a request are counted under `host:<operation>` in the exec metrics instead of `_background`.
