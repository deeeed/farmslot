- Local fleet slot checks and the pending-decision walk run in a `gateway-background` child process, off the request loop, and local fixture hashes are read in-process and reused while a file is unchanged. If the child is down, fleet refreshes fail and gateway.doctor's "Background process" check says so; `FARMSLOT_GATEWAY_BACKGROUND=0` runs these probes in-process.
- On local slots, fleet refresh, the branch watcher and the gateway update check read HEAD, refs and git config from the checkout's files instead of starting git, with the same answers; layouts outside the covered cases still run git.
- Publication secret scanning runs on a worker thread, so a large log no longer holds the gateway for seconds. Publication waits for the completed scan and refuses when the scan fails, is stopped, or 32 scans are already waiting.
- Runner progress files on remote slots are read through the node's `fs.readText` and `fs.isFile` instead of a shell per poll; nodes that do not declare the reads keep the shell read.
- GitHub reads and writes run in the gateway process over HTTP instead of one `gh` process per request, with ETag revalidation so unchanged data costs no rate limit. `gh` is still used to read the keyring token and sign-in status; the token is re-read at most once a minute, so `gh auth switch` takes effect within a minute. A slot PR found through a checkout's `upstream` or `gh repo set-default` remote is reported under that repository. `FARMSLOT_GITHUB_API_URL` points every GitHub host at one origin for fixtures and proofs; with it set, the keyring is never read and only `FARMSLOT_GITHUB_FIXTURE_TOKEN` is sent.
- Commands a host service starts outside a request are counted under `host:<operation>` in the exec metrics instead of `_background`.
