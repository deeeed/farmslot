- Pi and OpenCode model catalogs come from every execution node: the gateway runs `pi --list-models` and `opencode models` on each pool machine (20 s timeout) shortly after startup and while a picker watches, and keeps each node's last good listing. Dispatch never places a Pi or OpenCode model on a slot whose node lacks it: automatic selection skips those slots and a named slot is refused with the nodes that have the model. A node with no listing yet is not excluded. The Pi catalog no longer reads the gateway host's `~/.pi/agent` files. `native.session.catalog` lists, per execution node, the Pi and OpenCode models that node lists (with the saved set and default); a node that has not listed yet keeps the default. `dispatch.candidates` marks a free row ineligible, with the same reason, when its node lacks the chosen model.
