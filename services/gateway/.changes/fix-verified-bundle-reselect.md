- A slot whose node support selection moved to another bundle no longer runs farm commands from the bundle it selected before. The gateway caches a verified bundle per slot for 10 minutes, while the node may prune a bundle as soon as no slot selects it. When the local bundle returned to an earlier hash inside that window, commands were pointed at a deleted directory. On mini-ff-1 that made the dev-server shutdown fail, which left the sandbox gateway on its port, and the next dispatch failed with "port 8801 is already in use". A cached selected bundle now counts only while it is the slot's latest selection in this gateway and no selection for the slot is running, whether a command or prepare moved it. That covers a delivery that finishes after a newer one, the moment between the node pruning and the gateway hearing back, an activation that failed after selecting, and selections that overlapped: their order on the node is unknown, so nothing is served from the cache until a selection runs on its own. A delivery that finishes after a newer selection still returns its own, older command to its caller, as before. A selection made by another gateway on the same node is not seen.
