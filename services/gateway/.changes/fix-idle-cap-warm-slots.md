- The idle dev-server cap no longer exempts a keep-warm slot with no run forever: it keeps the server for 2 h instead of 15 min, then stops it. A keep-warm release on mini-mmt-3 had left the server and its prepare scope up for two days.
- When the cap stops a dev server on a slot with no owner, it also stops that slot's prepare scope, but only while the slot is ready with no live run, no other dev server is up and no capability lease holds it. The stop is fenced to the scope token read before the signals, under the same upkeep fence parked-work retention uses, and clears `warm` once settled; stopping the last dev server of a quiet slot with no recorded scope clears it too.
- Once per idle sweep, every slot is checked: a prepare scope that outlived its dev server on such a slot (dev servers definitely stopped, no unrecorded worker pane) stops after the same window, 2 h when keep-warm. A simulator or browser left up does not keep it. The window is kept on the slot row (`idle_prepare_scope`) and carried through fleet refreshes, so neither a restart, a refresh nor a not-yet-reported resource status resets it; only definite activity clears it (an owner, a live run, a running dev server or a lease; not a failed probe or a retention fence). A stop that throws retries after a full window. Identity files are read once per machine per sweep; ghost, misconfigured and offline slots are skipped, and failed checks are warned on every pass.
