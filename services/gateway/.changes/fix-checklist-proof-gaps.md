- A checklist step can declare the evidence it claims, as `- [ ] 9. Retain the failing baseline run [PROOF: artifacts/recipe-baseline-run]`. The declaration is frozen into the task's terminal contract at init, `./mark N` refuses the tick while that path is absent or empty, and completion refuses a checked step whose evidence is missing or was written after the claim. A step that declares nothing behaves exactly as before.
- An eval trial that runs with `review: false` is now marked unattended in its worker contract, and a refused completion ends such a run with the refusal as its reason instead of parking at a gate nobody attends. A blind trial that cannot clear an acceptance criterion is scored as a refusal naming the criterion, rather than stalling until an operator aborts it.
- A ledger written before the order rule still reads back its anomalies: marks recorded after a later-numbered step appear in the run's signal as `checklistTiming.outOfOrder`.
- A declared proof path counts as evidence only inside the task directory: one that resolves elsewhere through a symlink is refused, so a populated directory the run never produced cannot stand in for the proof.
- Checklist steps are claimed in order: a mark, and a child unit registered on a step, are both refused while an earlier step is unchecked. A step the template declares `[OPTIONAL: <when>]` can be skipped with `./mark N --skip "<reason>"`, which records the reason; any other step must be done, and completion refuses a checklist with a gap in it. A blind trial marked its changed-file CI gate twelve steps ahead of the work and nothing refused it.
- One step cannot be both `[OPTIONAL: <when>]` and `[DETERMINISTIC: <reference>]`: freezing a template that claims both refuses it, naming the step. A step a command receipt proves is not one a worker may declare inapplicable, and a run that accepted such a skip at the mark had no receipt to show any gate that later asked for one.
- A role sync only adopts `[OPTIONAL: <when>]` from a checklist the gateway just rendered from its template: after dispatch that file belongs to the agent, which must not be able to grant itself a skip the mark refused. A sync that cannot read the contract it already froze leaves it in place rather than rewriting it without that grant, so a transient read failure cannot turn an accepted skip into an unauthorized one for the rest of the run.
