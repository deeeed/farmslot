- Task inputs list the read-only reference checkouts a task is compared against. The writer resolves every `reference_repos` key (not only `mobile`) as a sibling of the slot checkout, probed on the machine that runs the task and recorded with the revision the worker cites; the task document gets a `Reference checkouts (read-only)` list and `inputs/reference-checkouts.json` carries the same set. A key that machine has not cloned is listed as absent, so a comparison the worker cannot make reads as blocked instead of unchecked, and it is no longer silently substituted with that project's slot checkout — the `<name>-ref` to `<name>-1` fallback is gone, because a slot checkout is a working tree other runs branch-switch and rewrite. A static review lists the references its support binding already read, in the same wording. A `<name>_library` key stays a recipe library bound through the support environment.
