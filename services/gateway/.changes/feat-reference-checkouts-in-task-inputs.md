- Task inputs list the read-only reference checkouts a task is compared against. A `reference_repos` entry opts in with `read_only: true`: the writer resolves it as a sibling of the slot checkout, probed in one command on the machine that runs the task and recorded with the revision the worker cites, the task document gets a `Reference checkouts (read-only)` list, and `inputs/reference-checkouts.json` carries the same set. The flag is required because several farms declare `reference_repos.mobile` as the slot's own Mobile tree, which their own checklist installs and boots; those keep today's behaviour and stay out of the list. A checkout the machine has not cloned is listed as absent, so a comparison the worker cannot make reads as blocked instead of unchecked, and it is never substituted with that project's slot checkout: the `<name>-ref` to `<name>-1` fallback is gone from both the task writer and the review templates, because a slot checkout is a working tree other runs branch-switch and rewrite. A static review lists the read-only references its support binding already read, in the same wording, and its bundle carries the file the document names. An operator plan is the task document itself, so it carries the same list.
