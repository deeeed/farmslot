- A pool or slot config that a fleet refresh can't read no longer drops the slot's resources silently. A pool file that doesn't parse (an edit read mid-write) is read once more. If it still fails, its slots keep their last good rows, and `fleet.status` reports `poolErrors` with the file and the parse error. A slot whose config fails to load carries `configError` on its row. Both are logged. A refresh asked for while one is running now runs once more after it, so an edit made during a slow refresh is no longer absorbed by it. Before, macpro-audiolab-1 read with no resources and stayed that way until something else refreshed (F306).
