- A pool or slot config that a fleet refresh can't read no longer drops the slot's resources silently. A pool file that doesn't parse (an edit read mid-write) is read once more. If it still fails, its slots keep their last good rows, and `fleet.status` reports `poolErrors` with the file and the parse error. A slot whose config fails to load keeps its pool resources, isn't probed or dispatched, and carries `configError` on its row. Both are logged, and the chat `fleet_refresh` tool returns them. Before, macpro-audiolab-1 read with no resources and stayed that way until something else refreshed (F306).
- A refresh asked for while one is running (an explicit refresh or a pool edit) now runs once more after it, so an edit made during a slow refresh is no longer absorbed by it. A stale `fleet.status` read joins the running refresh instead of queueing another.
- One slot whose config fails to load no longer marks its whole host SSH FAIL. The host check tries the host's other slots; if none loads, its rows show `-` for SSH.
- Command Center pool edits are written atomically (a temp file renamed over the pool), so a refresh never reads a half-written pool.
