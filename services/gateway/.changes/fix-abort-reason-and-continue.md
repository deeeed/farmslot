- Continue on a `runner unavailable` card now delivers a resume to the worker instead of only resuming the watch, so a pane holding a turn that died mid-flight is actually continued; the resume uses a one-shot pane instruction and does not spend the stuck/idle nudge budget, because a provider outage the operator fixed is not the worker stalling.
- Time a run spends blocked on a monitor decision is recorded as `monitorState.gateWaitMs` and excluded from the execution timeout, so answering a card no longer eats the worker's monitoring window and re-blocks the run as an interactive-handoff timeout seconds later.
- The resume and the usage-budget warning no longer share one message wrapper: the one-shot pane sender now carries the caller's exact text, dedup key and channel, so a worker resumed after a provider outage is no longer told to mark the checklist item it is still working on.
- Answering a monitor card also restarts the inactivity window, so a card the operator spent longer than the stuck timeout on does not spend a nudge in the same poll as the answer.
- A card still open when the gateway restarts has its wait credited when the monitor comes back, and a new monitoring window starts with no gate credit carried into it.
- The inactivity grace an answered card grants is withheld from a max-nudges card, where the worker is already stuck and Continue means resume nudging rather than wait another full stuck window.
- The gate-wait credit and its open-card marker are stored in one durable write, and a card raised before the first poll persist seeds the monitor state rather than going unmarked, so a restart while a card is open or a resume is being delivered cannot charge that wait to the worker. The open-wait marker now records the decision it belongs to, and only whatever answers that decision — its own settlement, or an operator extending the window from the card — may clear it, so a replayed monitor's open card keeps the marker that credits its wait after a restart. The card's id is allocated with its marker, so the decision an operator answers and the marker name the same thing. Gate credit is also fenced to the window it was measured in: a monitor whose window a replay has reset stops writing monitor state instead of charging the new window for cards it never showed, while still clearing the marker of its own answered card. The usage-budget guard no longer rebuilds monitor state from a field list, so a budget tick keeps the operator-wait and gate-wait accounting, and the open-card marker, that it does not own; a tick or a settlement that finishes after its monitor was replaced writes nothing at all, rather than putting a retired window back.
