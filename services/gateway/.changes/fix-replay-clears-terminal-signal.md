- A replayed worker no longer meets the finished signal its own `mark start` refuses. Clearing a finished `SIGNAL.json` before a worker-launch replay ran only for a native fresh restart, so on every other transport a replay of a step at or before dispatch left it in place and the new worker had no way past the start guard. Any such replay now clears it, and only it: each candidate is moved aside with one rename and judged on the bytes that moved, so a worker that rewrites its signal while the replay is deciding cannot have that file deleted; the snapshot goes back through a link that refuses an existing destination, so a signal written since is never overwritten. An aside left behind by a clear that was interrupted is swept back on the next one, including for a name whose signal is otherwise missing, and a signal that is still absent afterwards is named in the log. A `running` signal is preserved for admission to replace and a `blocked` one still resumes with its checked boxes.
