- A replayed worker no longer meets the finished signal its own `mark start` refuses. Clearing a finished `SIGNAL.json` before a worker-launch replay ran only for a native fresh restart, so on every other transport a replay of a step at or before dispatch left it in place and the new worker had no way past the start guard. Any such replay now clears it, and only it: the signal is moved aside and removed in one step, so a `running` signal that a worker writes while the replay is deciding is put back rather than lost, and a `blocked` signal still resumes with its checked boxes.
