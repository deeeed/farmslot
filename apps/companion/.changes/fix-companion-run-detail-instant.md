- Run Detail opens on the run instead of a skeleton. While run.get has nothing usable to show (it is loading, or its data would read as saved, as offline), a run in the Review or History list renders from that list row. Over a saved run.get the row shows only when it was updated later. Usable run.get data is not replaced by a row while a reread is pending. After a failed reread it stays on screen, with actions stopped, while its last good read is under 60 seconds old; after that a newer row shows. In the gate metrics, the cockpit counts and hints, the before/after panel and the focused-artifact card, what a row leaves out (the artifact manifest, large decision payloads such as review findings) reads as "not loaded" until the full run arrives, instead of as zero. A row whose run.get the gateway refuses, such as RUN_NOT_FOUND, is dropped. Run actions, including an interactive packet's terminal message and decision resolution and the cancelled run's slot release, wait for the current run.get. Only a run with no local copy at all shows the skeleton.
- While a list row is on screen, the status line dates it from the run list ("Saved run · age") without a second age for run.get, and still reports run.get's errors. Retry rereads the run list too when that list read failed.
- The saved-review card shows only for a run that has a saved review, and its Retry can be pressed after a failed read.
- The resource posture card's loading state holds the space of the card its read lands as, sized from the posture saved on the run, so a read that matches the saved posture no longer moves Timeline. It still moves by the difference when the live read lists a lease or resource wait the record doesn't, or lands as the shorter error card.
