- Run Detail opens on the run instead of a skeleton. A run in the Review or History list renders from that list row while its saved run.get is read from storage or the gateway answers, online or offline, and whichever of the two was updated later is shown. What a row leaves out (the artifact manifest, large decision payloads such as review findings) reads as "not loaded" until the full run arrives, instead of as zero. A row whose run.get the gateway refuses, such as RUN_NOT_FOUND, is dropped. Run actions, including an interactive packet's terminal message and decision resolution, wait for the current run.get. Only a run with no local copy at all shows the skeleton.
- While a list row is on screen, the status line dates it from the run list ("Saved run · age"), and a failed run read offers Retry.
- The saved-review card shows only for a run that has a saved review, and its Retry can be pressed after a failed read.
- The resource posture card's loading state holds the space of the card its read lands as, sized from the posture saved on the run, so a read that matches the saved posture no longer moves Timeline. It still moves by the difference when the live read lists a lease or resource wait the record doesn't, or lands as the shorter error card.
