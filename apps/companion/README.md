# Farmslot

Built by [Arthur Breton](https://siteed.net) as part of the Siteed software factory.

Project page: <https://siteed.net/projects/farmslot> · Privacy policy: <https://siteed.net/farmslot/privacy>

Mobile operator app for the Farmslot fleet — runs on iOS/iPadOS and Android via Expo development builds. Connects to the gateway over WebSocket and renders fleet status, runs, decisions, workers, PRs, terminals, and artifacts.

See [docs/PRD-mobile-companion-canonical.md](../../docs/PRD-mobile-companion-canonical.md) and [docs/ROADMAP.md](../../docs/ROADMAP.md).

Fresh installs do not ship with a gateway profile. Pair from Command Center by
scanning its QR code in Settings, or add a gateway URL manually for local
development.

## Quick start

```bash
yarn install                    # yarn 4 (Berry) — see "Package manager" below
yarn ios                        # build + install + launch with iOS picker/config
yarn ios:device                 # force the iOS physical-device picker/path
yarn android                    # local native build/install + launch on configured Android device
yarn android:device             # force Android picker even if local config remembers a device
yarn launch                     # human picker for iOS / Android / Metro only
yarn start                      # Metro only
```

`yarn typecheck` — TypeScript check, zero-tolerance.
`yarn eas:project` — confirm the local config is linked to the Expo project.

## Custom Metro port

Every Farmslot-managed React Native app should run Metro on an explicit, app- or slot-owned port. Do not rely on React Native's default port when multiple Expo/RN apps may run side by side.

This app defaults to `METRO_PORT=7677`, but the port is intentionally configurable per worktree/slot through `scripts/agentic/agentic.local.conf` or the environment.

### How the port is wired

The custom port is passed to Expo CLI by the local entrypoints:

```json
// package.json
"scripts": {
  "start": "bash scripts/agentic/start.sh",
  "ios": "bash scripts/agentic/run-ios.sh",
  "ios:device": "IOS_DEVICE_PICK=1 DEVICE_MODE=device bash scripts/agentic/run-ios.sh",
  "android": "bash scripts/agentic/run-android.sh",
  "android:device": "ANDROID_DEVICE_PICK=1 bash scripts/agentic/run-android.sh",
  "launch": "bash scripts/agentic/launch.sh"
}
```

`scripts/agentic/start.sh` starts Metro with `--dev-client --port "$METRO_PORT"`.

`scripts/agentic/run-ios.sh` remains the local iOS simulator entrypoint because
simulator builds are cheap and require macOS anyway. It sets `RCT_METRO_PORT`,
isolates the target simulator via `IOS_SIMULATOR`/`SIMULATOR`, and runs Expo with
the matching port.

## Android: EAS dev build only

Android native projects are generated by Expo CNG and gitignored. Local QA
builds use Expo's generated native project workflow. Use:

```bash
yarn android
```

That command runs `expo run:android --port "$METRO_PORT"` against the configured device.
It may generate a local `android/` directory while building; that directory is
ignored and can be deleted. For an explicit local EAS build, use:

```bash
yarn build:android:development
```

## Local device config per worktree

Each worktree can target a different real device or simulator via an ignored
local file:

```bash
cp scripts/agentic/agentic.local.conf.example scripts/agentic/agentic.local.conf
```

`METRO_PORT` is the canonical Expo/RN port variable. `WATCHER_PORT` is accepted
only as a legacy alias for older Farmslot/project scripts.

Example for a real Android device on the local Wi-Fi/LAN:

```bash
ADB_SERIAL=YOUR_DEVICE_SERIAL
METRO_CONNECTION=lan
```

Example for an iOS simulator:

```bash
DEVICE_MODE=simulator
IOS_SIMULATOR="iPhone 16 Pro"
METRO_CONNECTION=localhost
```

With `METRO_CONNECTION=auto`, the scripts choose localhost for simulator/emulator
flows and LAN for physical-device flows. With `METRO_CONNECTION=lan`, scripts
auto-detect the Mac's LAN IP, advertise Metro on that host, and derive
`EXPO_PUBLIC_GATEWAY_URL=ws://<LAN-IP>:7777/ws` unless you set it explicitly.
Use LAN when the phone and Mac are on the same network and you want to QA without
relying on USB port reversal.

If no target is configured and a command runs in an interactive terminal,
`yarn ios`, `yarn ios:device`, `yarn android`, and `yarn android:device` use
platform pickers. In non-interactive/Farmslot runs, inject deterministic env such
as `IOS_SIMULATOR`, `IOS_DEVICE_UDID`, or `ADB_SERIAL`.

### Why this works

`expo run:ios --port <N>` does two things in one shot:

1. **Bakes the port into the native binary** by passing `RCT_METRO_PORT=<N>` as an environment variable to `xcodebuild`. React Native reads this at compile time via the `RCT_METRO_PORT` macro and uses it as the default `jsLocation` in `RCTBundleURLProvider`. See `node_modules/@expo/cli/build/src/run/ios/XcodeBuild.js` (`env.RCT_METRO_PORT = port.toString()`).
2. **Starts Metro on the same port** and launches the dev client with the matching deep-link URL (`farmslot-development://expo-development-client/?url=http://<host>:<N>`).

`yarn start` only does step 2 — it just runs Metro. So `yarn start` alone is fine **after** the binary has been built once with `yarn ios` (which baked the port in).

### Symptom: app loads from a different Metro port than expected

This usually means the binary was built without the project script that forwards `--port "$METRO_PORT"`. Common ways this happens:

- Someone ran `npx expo run:ios` directly
- Someone ran `expo run:ios` without forwarding the configured port
- An IDE or AI tool launched the build with its own incantation

**Fix:** rebuild via `yarn ios` or `yarn android` so the native binary and Metro agree on the configured port. Restarting Metro alone will not rebake the native default.

### Don't patch native iOS source for ports

There used to be plugins that patched `AppDelegate.swift`/`AppDelegate.mm` to
override `jsLocation` at runtime. They were:

1. **Looking for the wrong file** (`AppDelegate.swift`) when Expo SDK 52 generates `AppDelegate.mm` — so the patch silently never applied.
2. **Redundant** — `--port` already does the job via `RCT_METRO_PORT`.
3. **Bypassed by direct Expo CLI invocation** — the CLI can start Metro on its default port when the project entrypoint does not forward the configured port.

They've been deleted. **Don't bring iOS source patches back.** If the
configured `--port` stops working, fix `scripts/agentic/run-ios.sh` or package
scripts, not generated files under `ios/`.

### Don't patch generated native source

`android` and `ios` are gitignored generated directories, not source of truth. Keep native configuration in
`app.config.ts`, config plugins, dependencies, and `eas.json`.

If local `android/` or `ios/` directories appear from troubleshooting, they can
be deleted. EAS Build/Expo CNG regenerates native projects from config when
native directories are absent from the project upload.

## Package manager

Yarn 4.5.3 (Berry) with `nodeLinker: node-modules` (Expo and React Native don't support PnP).

```bash
corepack enable                 # one-time
yarn install                    # honors packageManager field in package.json
```

**Don't run `npm install` here.** It will write a `package-lock.json` (gitignored) and silently desync from `yarn.lock`, then `npx expo install` will create more confusion. If you see `package-lock.json` appear, delete it and re-run `yarn install`.

## Architecture

```
@farmslot/protocol (file: dep)  --+
                                   +--> GatewayClient ----> Zustand stores ----> Expo Router screens
gateway (ws://<host>:7777/ws) ----+
```

- **`src/lib/gateway-client.ts`** — WebSocket client adapted from the web UI. AppState-aware: disconnects on background, reconnects on foreground.
- **`src/store/`** — Zustand stores (`connection`, `fleet`, `runs`, `decisions`, `filters`).
- **`src/app/`** — Expo Router file-based routes (tabs + stack).
- **`src/components/`** — Shared cards, viewer, banners.
- **`src/lib/artifact-url.ts`** — Builds gateway artifact HTTP URLs from the WS URL.

The app is **online-only**. There's no offline cache, no pull-to-refresh — every list updates live via WS events (`fleet.updated`, `run.updated`, `slot.changed`, `decision.new`, etc.).

## Variants

All variants use the first-party Siteed namespace and install side by side:

| Variant       | App name           | Bundle/package ID                 | Scheme                    | Icon/accent |
| ------------- | ------------------ | --------------------------------- | ------------------------- | ----------- |
| `development` | `Farmslot Dev`     | `net.siteed.farmslot.development` | `farmslot-development://` | crimson     |
| `preview`     | `Farmslot Preview` | `net.siteed.farmslot.preview`     | `farmslot-preview://`     | amber       |
| `production`  | `Farmslot`         | `net.siteed.farmslot`             | `farmslot://`             | indigo      |

Env files: `.env.development`, `.env.preview`, `.env.production`, `.env.sample`; personal defaults belong in ignored `.env.local` or `.env.<variant>.local` files. Loaded by `dotenv-flow` in `app.config.ts`, validated by Joi. Committed env files intentionally leave gateway URLs blank so distributable builds start unpaired and users add a profile by scanning a Command Center QR code. All variants keep the canonical Expo slug for the linked EAS project, while non-production variants get unique bundle/package IDs and schemes so Android does not show a chooser between dev/preview/prod handlers. Runtime environment identity is intentionally minimal in the UI: non-production builds draw a thin top accent strip, while full variant/bundle/scheme/Metro/update details live in Settings → App Environment. Recipe-driven proof overlays should be supplied by Farmslot runtime/recipe tooling, not by an always-on app HUD.

## EAS Build and Update

The app is linked to the configured EAS project ID
(`5673e87d-de68-4685-9d17-03533e7d63de` in this branch). `app.config.ts` keeps native app metadata in Expo config:

- `updates.url` is `https://u.expo.dev/${EAS_PROJECT_ID}`
- `extra.eas.projectId` is set for EAS services
- `runtimeVersion` uses Expo's `appVersion` policy, so OTA updates target binaries with the same app `version`
- `expo-updates` is enabled with embedded-update fallback; publish UI-only fixes with `yarn update:development`, `yarn update:preview`, or `yarn update:production` after validating the matching dev-client/TestFlight/internal build
- the app checks for OTA updates on launch and auto-reloads after downloading a compatible update; Settings includes an OTA status card for manual checks and diagnostics

The EAS scripts invoke `yarn dlx eas-cli@18.13.0` so the companion uses the
current compatible CLI even if the globally installed `eas` is older. Keep
`eas.json`'s `cli.version` in sync with that script pin when upgrading.

```bash
yarn eas:project
yarn build:android:development
yarn update:development --message "manual test update"
yarn build:ios:development
yarn build:ios:preview
yarn build:ios:production
yarn build:android:preview-apk
yarn release:preview              # dry-run plan
yarn release:preview --execute    # build + update preview
yarn release:production           # dry-run plan
yarn release:production --execute # build + update production
yarn submit:production            # dry-run submit plan
yarn submit:production --execute  # submit latest production builds
```

`preview_apk` uses the same `preview` update channel as the preview iOS/internal
build so a single `yarn update:preview --message "..."` reaches both. Release
wrappers are dry-run by default and require `--execute` before mutating EAS.

Do not publish a production update/build/submit without confirming the gateway
URL, app variant, store metadata, and review evidence for the build being shipped.

## Troubleshooting

**Black screen on launch.** Metro isn't reachable on the port the binary expects. Check `lsof -ti:${METRO_PORT:-7677}` — if empty, run `yarn start`. If Metro is up on a different port, rebuild with `yarn ios` or `yarn android` to rebake the configured port.

**`Unable to resolve module ./node_modules/expo-router/entry`.** Stale Metro/Watchman cache after a `yarn install`. Fix:

```bash
REPO_ROOT=$(git rev-parse --show-toplevel)
watchman watch-del "$REPO_ROOT" && watchman watch-project "$REPO_ROOT"
yarn start --clear
```

**Pods rebuild from scratch every time.** Yarn install changed file inodes inside `node_modules`, which Xcode treats as podspec changes. Annoying but cosmetic — incremental builds resume after the first run on a fresh install.
