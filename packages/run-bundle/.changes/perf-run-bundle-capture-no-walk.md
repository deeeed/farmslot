- Store admission charges come from a per-process cache that is reused while the store root, `sha256/`, `usage/` and `availability/` keep their stamps, instead of walking every bundle record and availability file two to four times per capture. Own record writes and bundle publishes keep it current; any other writer changes a stamp and forces one walk. `reservations/` and `staging/` are still walked on every read. Captures run housekeeping only at the archive threshold, when their declared bytes would cross the cap, or when an artifact has no declared size (`housekeepBeforeCapture`). Housekeeping reads capture intents through a stamp cache. The kept acquisition footprints move to `usage/acquisition/footprints.json`; the old file is read until the first save, then removed.
