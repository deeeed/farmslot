- The task runtime (task init and verify) runs in a child node process instead of a worker thread. tsx's ESM loader thread owns an esbuild service child. When a task worker thread exited, that child exited too and nobody reaped it, so each init or verify left one zombie on the node (238 on macpro after two days). The task process keeps its environment and CLI config private as before, and subprocess groups are still tracked and closed out, now over IPC. If the node dies before the task's result is delivered, a watchdog thread in the task stops its tracked subprocess groups and then the task's own group, even while the task is blocked in a synchronous call. A task that exits uncleanly has its own group killed as it is reaped, and a cancel after the task exited still stops its tracked groups. A task inherits NODE_OPTIONS without module preloads (--import, --require, loaders), since it loads tsx itself.
