- The task runtime (task init and verify) runs in a child node process instead of a worker thread. tsx's ESM loader thread owns an esbuild service child. When a task worker thread exited, that child exited too and nobody reaped it, so each init or verify left one zombie on the node (238 on macpro after two days). The task process keeps its environment and CLI config private as before, and subprocess groups are still tracked and closed out, now over IPC.
