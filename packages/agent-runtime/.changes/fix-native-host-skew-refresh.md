- A native host left on an older runtime no longer blocks launches while its live sessions are idle. A client given a refresh policy (`setRefreshPolicy`) stops a skewed host whose live sessions are all idle and not kept by the policy, on a later launch or `refreshStaleHost()`. A request from the same client that adds work (a launch, message, steer, compaction or approval change) and is already on its way holds the host. Reads, interrupts, closes and answers never wait for a refresh. The supervisor's cleanup stops and confirms each runner, and the next host keeps the journals and reports those sessions for resume. Hosts from this version fence admissions and new input for that stop (`prepareUpgrade` with `idleRunners`, lifting after a minute without the stop) and name any session still sending, compacting, finishing a turn or waiting on a request. A session with a turn or request in flight, or one the policy keeps, holds the host, and the version-skew error names it. Without a policy, a client refreshes only from `warm()`, and only a host whose runners have all stopped, as before. `liveSessions()` lists a running host's live sessions across owners without starting one. A legacy host with no upgrade fence is stopped the same way, relying on the client's census. A client whose process runs older code than its own checkout (updated, not restarted) refuses to refresh and says to restart it.
