- A native host left on an older runtime no longer blocks launches while its live sessions are idle. A client given a refresh policy (`setRefreshPolicy`) stops a skewed host whose live sessions are all idle and not kept by the policy, on the next launch or `refreshStaleHost()`. Requests already on their way finish first. The supervisor's cleanup stops and confirms each runner, and the next host keeps the journals and reports those sessions for resume. Hosts from this version fence admissions and new input for that stop (`prepareUpgrade` with `idleRunners`) and name any session still sending, compacting, finishing a turn or waiting on a request. A session with a turn or request in flight, or one the policy keeps, holds the host, and the version-skew error names it. Without a policy, only a host whose runners have all stopped is refreshed, as before. `liveSessions()` lists a running host's live sessions across owners without starting one.
