- A plain `mark complete` now checks that the checklist is complete, not only `mark complete --mark-last`. `mark no-change` keeps its documented early exit with later rows open. GLM evals 4cba5c2f and ee2a98b8 both completed with zero steps marked and were reported successful over an untouched checklist; the order rule could not catch it either, since it only reports steps left behind the last checked one.
- A refused completion ends an unattended run only when every step is marked, so the worker has nothing left to try. A premature complete, or one missing an artifact the worker can still write, is an ordinary refusal that leaves the signal alone — ending the run there sent it to review while the worker was still working.
- `mark start` no longer re-opens a run that finished. A start on a `complete` or `no-change` signal used to fall through and overwrite the record of a run parked at its human gate. A blocked run still resumes and keeps its checked boxes, and a re-dispatch clears the signal first.
