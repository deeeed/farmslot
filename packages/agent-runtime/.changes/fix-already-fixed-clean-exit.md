- A no-change exit no longer needs a deterministic check receipt it cannot record. `mark no-change` (already fixed, or not reproducible) changed nothing, so a changed-file check has nothing to validate — and its receipt can only be recorded by marking that step, which the order rule refuses while an earlier reproduction step is unchecked, and that step cannot be ticked honestly when the bug does not reproduce. Run c2821858 (TAT-4685) had no exit at all as a result. A receipt that _was_ recorded still has to pass: only missing ones are waived, and only for a no-change exit.
