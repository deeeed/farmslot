- Add `RunListRow`, the honest type of a `run.list` row, and `runListRow(run)`, the row the gateway serves: the run without its heavy keys. It drops `resourcePosture`, `sessionUsage`, `visualJudgmentReceipts` and `templateProvenance`, leaves the output file manifest out as `trimRunForList` does, and keeps the step outputs list surfaces read (through `listStepOutputs`, each kept key in the bounded shape its view reads, CI check names and fix labels capped) plus the diff stat and each step's videos, before/after visuals and diff files. Decisions are the ones `trimRunForList` serves, without their selection, attestation and the heavy keys of their payload; engine state, agent contexts, metrics, the ticket, the review result and the review subject leave out only their heavy keys. Every small field stays. A row says what it left out: `payloadTrimmed` names payload keys, `outputsTrimmed: true` marks a step, `detailTrimmed: true` marks a row that left out any other heavy key, and `runHasTrimmedDetail` reads all of them. Row versions are still `sha256(trimRunForList(run))`.
- `RunEvidenceSummary` also carries `diffStat`, `diffArtifactPath` (the file `diffArtifactCandidate`, now shared from protocol, picks for a run's Diff action) and `stepArtifacts`, the eval catalog's counts of a run's step-output artifacts (`summarizeStepArtifacts`). `summarizeRunEvidence` always computes from what it is given; `runListEvidenceSummary(row)` returns a row's served summary, or computes one from a row cached before slim rows.
- The client cache never derives a run detail version by hashing a slim row: until the version list is held, a slim row does not mark its stored detail as changed, so a cold start no longer rereads `run.get` for every listed run. Full rows from an older gateway keep the derived version.
