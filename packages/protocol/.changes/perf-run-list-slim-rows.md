- Add `RunListRow`, the honest type of a `run.list` row, and `runListRow(run)`, the slim projection the gateway serves. It drops `resourcePosture`, `sessionUsage`, `visualJudgmentReceipts` and `templateProvenance`, leaves the output file manifest out as `trimRunForList` does, keeps only the step, decision and engine-state fields list surfaces read (step outputs through `listStepOutputs`, each kept key in the bounded shape its view reads), names every payload key it leaves out in `payloadTrimmed` and marks a step that lost inputs or output values with `outputsTrimmed: true` (CI check names and fix labels are capped), so `runHasTrimmedDetail` reports the row as trimmed, and attaches `evidenceSummary` computed from the full run. Agent contexts, metrics, the ticket, the review result and the review subject leave out only their heavy keys (visual-review blobs, session archive and usage; checklist timing; the ticket description; the review text and line comments; the pull request body; a ready gate's `gateSummary`), and such a row carries `detailTrimmed: true`. Row versions are still `sha256(trimRunForList(run))`.
- `RunEvidenceSummary` also carries `diffStat`, `artifactBytes`, visual, validation and review evidence counts, and `diffArtifactPath` (the file `diffArtifactCandidate`, now shared from protocol, picks for a run's Diff action). `summarizeRunEvidence` always computes from what it is given; `runListEvidenceSummary(row)` returns a row's served summary, or computes one from a row cached before slim rows.
- The client cache never derives a run detail version by hashing a slim row: until the version list is held, a slim row does not mark its stored detail as changed, so a cold start no longer rereads `run.get` for every listed run. Full rows from an older gateway keep the derived version.
